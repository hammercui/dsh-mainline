# 主线（dsh-mainline）

给 vibe coding 用的只读侧边栏仪表盘：显示项目路线图、当前动作与范围偏离，并在 **0.4 会话能力视图**中查看 Skill / MCP 使用证据。

**只观察，不干预**：不拦截、纠正或改写工具调用，不替你修改路线图，不把工具调用次数当成任务完成度。路线图状态由项目配置驱动。

## 安装

将仓库下载到本地，在 DSH 会话中让 Agent 使用 `plugin_manager` 安装：

```json
{ "action": "install_bundle", "target": "<仓库绝对路径>" }
```

将占位符替换为你的实际路径，不要直接复制占位符执行。安装完成后按工具返回的应用状态确认是否需要重启；侧边栏入口为「主线」。使用支持插件清单所声明版本与服务的 DSH 运行时。

## 0.4.6：会话能力

新增紧凑/详细密度切换（默认紧凑）、用户明确设定的“从当前轮开始新任务”范围，跨轮技能显示在“本任务此前加载”。范围仅当前面板内按 session 分开保存，关闭/重载清除；不按时间猜任务，不变更会话日志。最近成功加载的详情保留事件 seq、轮次、用户指定/模型主动来源，失败重试不抹掉成功依据。当前未接入原消息跳转，事件位置仅用于核对；没有虚构链接。

当前工作看板默认只展开本轮成功加载/正在加载的技能，历史记录收起；「需关注」跨本轮和历史列出最近加载异常。卡片使用可换行流式布局，窄侧栏单列、宽面板多列，阅读顺序保持 DOM 次序。技能族标签只按明确名称前缀约定（Hammercui/Lark/Office/Cordis），不是已核验的作者/包来源；其余为未分族。

当前上下文保留情况仍不可确认：native surface 替换按当前表面顺序处理，且消息投影可变换原节点内容，单纯保留 Skill 的历史 seq 不足以证明说明仍发给模型。因此不把历史加载标为“上下文中”，也不把加载数量当成工作质量分数。

每个 Skill 展示最近一次成功加载文本的 token 粗估，并在详情展示已统计加载的累计值与缺失次数；顶部汇总仅针对保留条目。口径为 `ceil(ASCII 码点数 / 4 + 非 ASCII 码点数)`，包括返回的包装和说明文本，不是模型精确 tokenizer、实际计费或当前上下文占用，也不包含后续参考文件、工具执行及模型输出。重复加载重复计入；失败不新增，空文本/超过 1M UTF-16 单元/无法完整统计则显示 `—`，不当作零。投影只存数值，不额外保存正文。

Skill 状态小点区分本轮与历史：本轮成功加载且轮次运行时绿色呼吸，轮次结束后常亮；此前加载为灰色（不等于确定未参与）。正在加载为蓝点，异常为琥珀色；重复加载失败不会抹掉本轮既有成功证据，异常仍显示解释并进入「需关注」。动画遵守 `prefers-reduced-motion`。这些都是日志证据，不是模型内部遵循情况的检测。

采用单层列表，默认展示名称、两行用途和最近状态；次数、完整说明与时间放入「详情」。可筛选「全部 / 需关注」，正常记录不显示“失败 0”。Skill 用途取自会话内可信的技能目录事件，无历史说明时明确提示，不按名称猜测。能力页不显示无关的路线图偏离底栏。

“最近加载失败”指最近一次读取 Skill 说明失败，不代表任务失败；已有成功加载记录仍保留。

右侧「主线」面板可切换「路线图 / 会话能力」。会话能力视图跟随所选会话，通过宿主的原生 Session Projection / wire 获取证据，而不是另建一份会话日志。当前覆盖原生 Skill / MCP 工具调用及明确的用户 Skill 指令；PTC、封装工具内部调用可能未计入。最多保留 80 个能力条目，达到上限时淘汰最早建立的条目。

- **Skill 已加载**：会话日志中出现加载证据；不等于模型此刻仍在遵循，也不证明每条规则都已执行。
- **当前遵循**：除非有明确、可验证的当前状态，不把历史加载记录标成「正在遵循」。
- **MCP 工具使用证据**：显示可识别的工具调用；从工具标识推断的 server 只是归属线索，**不是连接、在线或健康状态**。没有证据也不代表未连接。
- **回放与重启**：原生投影可从持久会话事件重建其覆盖的证据；这不代表全部运行时状态都有历史。旧的范围观察事件环、告警与计数仍是内存数据，重启清零。

## 接入项目

1. 让 Agent「给这个项目接入主线」，使用随包提供的 `mainline-onboarding` skill；已有路线图时可从中提炼里程碑。
2. 或在项目根创建 `.dsh/mainline.json`，参考 [配置模板](<mainline.config.example.json>)，填写项目根、里程碑、任务与允许/禁止路径。
3. 在主线面板确认项目及配置状态。配置热加载；解析失败时保留上次成功的配置并显示错误。

配置可作为项目计划提交，但应先审查机器绝对路径、私有任务和敏感信息。本插件仓库默认忽略本地 `.dsh/`，仅发布通用模板。

```json
{
  "project": "your-project",
  "root": ".",
  "activeMilestone": "M1",
  "activeTask": "M1-1",
  "forbid": ["**/.env*", "**/secrets/**"],
  "milestones": [{
    "id": "M1",
    "title": "第一个里程碑",
    "allow": ["$WS/src/**", "$WS/.dsh/mainline.json"],
    "tasks": [{ "id": "M1-1", "title": "实现功能", "acceptance": ["可验证的验收条件"] }]
  }]
}
```

任务与里程碑支持 `todo` / `doing` / `done`；`activeTask` 标记当前位置。验收标准是说明，不是自动验证结果。`$WS` 表示配置解析后的项目根，`~` 表示用户目录；通配符支持 `**`、`*`、`?`、`{a,b}`，普通路径按前缀匹配。

## 路线图与面板

左侧主面板适合看完整路线图，右侧栏适合跟随当前会话。树状图和工作流图共享同一份计划：

| 视图 | 用途 |
|---|---|
| 树状图 | 自上而下查看里程碑、任务、完成状态及当前位置 |
| 工作流图 | 稳定双列布局，查看父子关系；窗口变化不重新分带排列，支持缩放、平移和复位 |

工作流画布使用可用面板高度；窄栏通过缩放、平移查看，避免改变布局后丢失阅读位置。节点可折叠、展开并查看详情；关键里程碑用星标突出。偏离只进入告警及明细，不画成路线图分支。

「刷新」只重新获取观察数据和实时流，不重载整个页面。代码更新是否可热加载由宿主决定；未反映时按安装工具提示重新激活或重启桌面端，不保证只刷新页面即可加载新代码。

## 四色范围判定

| 级别 | 含义 |
|---|---|
| ⚪ 仅展示 | 命令、读取及未纳入规则的工具，不做范围判定 |
| 🟢 允许 | 写入目标命中当前里程碑的 `allow` |
| 🟡 计划外 | 写入目标未命中 `allow`，或无法解析目标 |
| 🔴 禁止 | 命中项目或里程碑的 `forbid`，优先于允许规则 |

绿色表示写入在范围内，**不表示任务已完成**。工具结果的错误标志不是语义正确性的证明。里程碑切换查看不回写配置；观察记录按发生时的里程碑归属。

## 配置查找与只读接口

配置优先级：插件 `configFile` → `DSH_SCOPE_DRIFT_CONFIG` → 当前会话工作区的 `.dsh/mainline.json` → 工作区 `mainline.json`（兼容旧名 `scope-drift.json`）→ 宿主 cwd / 用户目录下的 `.dsh/mainline.json`。

| 路由 | 内容 |
|---|---|
| `GET /dsh-mainline/state` | 观察快照、路线图配置与已知会话 |
| `GET /dsh-mainline/state?session=<id>` | 按会话筛选观察数据与项目配置 |
| `GET /dsh-mainline/events` | SSE 快照及增量；支持 `?session=` |
| `GET /dsh-mainline/export` | 机器视角观察数据导出 |

这些观察接口仅接受回环请求；带 `Origin` 时也必须为本机来源。原生会话能力投影与上述内存观察环是不同的数据通道。观察事件环最多 200 条、告警最多 100 条，同级别、工具、目标的告警合并计数。导出、截图和静态预览可能包含工作区路径及会话内容，分享前必须审查。

多项目判定按调用所属会话的配置进行。`/goal` 只作为目标展示，不自动推进任务状态，也不由本插件创建或更新。

## 开发与验证

无额外构建步骤；[宿主入口](<lib/index.js>) 和 [客户端](<lib/client.js>) 是运行产物。

```powershell
npm ci --ignore-scripts
npm test
node scripts/render-probe.cjs --port=<当前GUI端口>
node scripts/preview-flow.cjs --port=<当前GUI端口>
```

将端口占位符替换为当前 DSH GUI 端口；桌面重启后端口可能改变。后两个脚本读取真实观察快照，不是完整宿主集成测试。预览脚本会生成本地 HTML，mock React 不运行 effect，无法替代真实页面的交互和布局验证。Smoke 测试会创建并清理临时文件。

发布前使用明确文件清单，排除本地配置、依赖、密钥、日志、截图和生成预览。本仓库采用 [MIT License](<LICENSE>)。
